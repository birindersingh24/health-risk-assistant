# Problem list data quality

> **Mock document for a software demo. Not clinical guidance; do not use for patient care.**
> Example Clinic internal policy.

## Why it matters

Risk scores, care-gap checks and dose checks all read the problem list. A wrong entry changes their output: a coded diabetes adds three risk points, and a missing CKD code hides the need for dose checks. Problems in the list are therefore findings in their own right.

## Diagnosis without supporting data

A diagnosis is supported when results, medicines or a specialist letter back it up. Flag an entry as "needs confirmation" when nothing supports it. Example: type 2 diabetes is coded, but every HbA1c is normal and the patient takes no diabetes medicine. Common causes are codes carried over from an outside record, a code meant for a family member, or a "rule out" diagnosis saved as confirmed.

While a diagnosis needs confirmation, do not start or change treatment because of it, and report any risk score both with and without it.

## Data supporting a diagnosis that is not recorded

Flag "possible unrecorded diagnosis" when results meet a protocol's definition but the problem list lacks the code. Examples: two HbA1c results of 6.5% or more on different dates (dm-01), or eGFR below 60 for more than three months (ckd-01).

## Out-of-date entries

Flag an entry when its detail no longer matches the latest results, for example CKD coded as stage 3a while the latest eGFR is in the G3b range.

## Who fixes it

Only the patient's clinician changes the problem list, after review. Software must never delete or edit an entry. It reports the mismatch, the evidence on each side, and the route in ops-01.
